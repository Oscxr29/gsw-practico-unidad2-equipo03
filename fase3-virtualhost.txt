COMANDOS EJECUTADOS (WSL2 / Ubuntu)
=====================================================================

# 1. Crear carpeta del sitio
sudo mkdir -p /var/www/dulcehogar.local
sudo chown -R www-data:www-data /var/www/dulcehogar.local
echo "<h1>Dulce Hogar</h1>" | sudo tee /var/www/dulcehogar.local/index.html

# 2. Crear contenedor Express
mkdir ~/dulcehogar-api
cd ~/dulcehogar-api
npm init -y
npm install express
nano index.js

# 3. Registrar servicio systemd
sudo nano /etc/systemd/system/dulcehogar.service
sudo systemctl daemon-reload
sudo systemctl enable dulcehogar
sudo systemctl start dulcehogar
sudo systemctl status dulcehogar

# 4. Habilitar módulos proxy
sudo a2enmod proxy proxy_http headers
sudo systemctl restart apache2

# 5. Crear Virtual Host
sudo nano /etc/apache2/sites-available/dulcehogar.local.conf
sudo a2ensite dulcehogar.local.conf
sudo apache2ctl configtest
sudo systemctl reload apache2
echo "127.0.0.1 dulcehogar.local" | sudo tee -a /etc/hosts

# 6. Windows PowerShell (Admin)
Add-Content C:\Windows\System32\drivers\etc\hosts "127.0.0.1 dulcehogar.local"
Add-Content C:\Windows\System32\drivers\etc\hosts "::1 dulcehogar.local"

# 7. Probar
curl "http://dulcehogar.local/api/saludo?nombre=Equipo"
curl "http://dulcehogar.local/api/cotizacion?nombre=Isvi&telefono=7777&producto=pastel"

=====================================================================
CONTENIDO DE index.js
=====================================================================

const express = require('express');
const app = express();
const PORT = 9000;

app.get('/api/saludo', (req, res) => {
  const nombre = req.query.nombre || 'Mundo';
  res.json({ mensaje: `Hola, ${nombre}`, desde: 'dulcehogar:9000' });
});

app.get('/api/cotizacion', (req, res) => {
  const { nombre, telefono, producto } = req.query;
  res.json({
    cotizacionId: Date.now(),
    nombre: nombre || 'Sin nombre',
    telefono: telefono || 'Sin telefono',
    producto: producto || 'Sin producto',
    fecha: new Date().toISOString().split('T')[0],
    estado: 'pendiente'
  });
});

app.listen(PORT, () => {
  console.log(`dulcehogar escuchando en http://localhost:${PORT}`);
});

=====================================================================
PREGUNTA 1: ¿Qué hace ProxyPass /api http://localhost:9000/api?
=====================================================================

Reenvía todas las peticiones que empiecen con /api a la aplicación 
backend Express que corre en localhost:9000. Cuando el cliente pide
http://dulcehogar.local/api/saludo, Apache no procesa esa petición,
sino que la transfiere internamente a http://localhost:9000/api/saludo,
recibe la respuesta del contenedor y se la devuelve al cliente como si
fuera suya. El cliente nunca sabe que hay dos servidores trabajando.

=====================================================================
PREGUNTA 2: ¿Diferencia entre ProxyPass y ProxyPassReverse?
=====================================================================

ProxyPass se encarga de reenviar las peticiones del cliente desde Apache 
hacia el backend Express, mientras que ProxyPassReverse ajusta determinadas 
cabeceras de respuesta del backend, especialmente Location, para que las 
redirecciones utilicen la dirección del proxy en lugar de la dirección 
interna del backend.

Dicho de otra manera, ProxyPass indica «envía esta petición al backend» 
y ProxyPassReverse permite que, cuando el backend responda con una redirección, 
Apache ajuste la dirección correspondiente para que el cliente continúe 
accediendo mediante el dominio configurado.

De esta forma, ambas directivas facilitan la comunicación entre Apache y Express 
sin que el cliente tenga que acceder directamente al puerto 9000.

Nota técnica adicional (Rol: Adm. de Redes / Proxy):
- ProxyPreserveHost On: Conserva la cabecera Host original del cliente
  (dulcehogar.local) en lugar de sobrescribirla con localhost:9000. Esto
  es fundamental para que el backend reconozca el dominio solicitado.
- Aislamiento de capas: El puerto 9000 queda confinado a la red interna
  (localhost/WSL2), mientras que el puerto 80 queda expuesto al cliente,
  garantizando que toda petición pase por el filtrado y logs de Apache.
=====================================================================
PREGUNTA 3: Reto — ¿Qué pasa si configtest falla?
=====================================================================

Si configtest falla, significa que Apache ha detectado un problema en 
la configuración analizada. Antes de recargar o reiniciar el servicio, 
se debe identificar y corregir el error. Si Apache ya estaba funcionando, 
podría continuar utilizando la configuración anterior, dependiendo de la 
situación.

Pasos para depurar el problema:

Ejecutar sudo apache2ctl configtest y leer el mensaje de error.

Revisar el archivo de configuración indicado, prestando atención a las 
directivas, los nombres de los módulos y el cierre de las etiquetas, 
como </VirtualHost>.

Verificar que los módulos necesarios estén habilitados con sudo a2enmod 
proxy proxy_http headers.

Volver a ejecutar sudo apache2ctl configtest y, cuando indique Syntax OK, 
recargar Apache con sudo systemctl reload apache2.

=====================================================================
PREGUNTA 4: ¿Por qué es prueba de conexión U1 + U2?
=====================================================================

La respuesta JSON obtenida mediante curl es una evidencia de la integración 
entre Apache y Express. La petición se realiza a través del dominio 
dulcehogar.local, que utiliza el puerto 80 de Apache, y se reenvía al 
backend Express, que escucha en el puerto 9000.

Respuesta obtenida:

{"mensaje":"Hola, Equipo","desde":"dulcehogar:9000"}

Esta respuesta, obtenida al realizar la solicitud a través del dominio 
configurado en Apache, junto con la configuración del Virtual Host y las 
pruebas de conectividad, permite comprobar que ambos componentes se
comunican correctamente. Apache recibe la petición y la reenvía a Express, 
que procesa la solicitud y devuelve la respuesta JSON al cliente.
